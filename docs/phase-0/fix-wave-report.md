## I1 — the determinism result (most important item)

**Fix applied:** `thread_count: 1` added to `tools/oracle/gen_smoke_fixture.py`'s `PARAMS`
(matching the CLI oracle's pinned `-T 1`). Fixture regenerated; `smoke_params.json` now
carries `"thread_count": 1`. `smoke_predictions.json` was **not** modified by the
regeneration (byte-identical before/after adding the pin).

**Empirical hazard test** (throwaway script, not committed, run via `uv run --project
tools/oracle`): trained the same 40-row/20-iteration fixture with `random_seed=42` fixed and
`thread_count` varied — unset (CatBoost default, this machine has 32 cores), `1`, and `8` —
two independent processes per setting.

Result:

```json
{
  "no_pin_repeatable": true,
  "tc1_repeatable": true,
  "tc8_repeatable": true,
  "tc1_vs_tc8 (THE HAZARD)": true,
  "tc1_vs_no_pin": true
}
```

**All predictions were bit-identical across every thread_count setting tested, including
against the unpinned default.** The hazard the review flagged — the two oracles disagreeing
about whether thread count affects determinism — did **not** manifest empirically on this
fixture, on this machine (32 cores), for these params (20 iterations, depth 4, 40 rows).

This is a genuine negative result, reported honestly, with an important caveat: it is
negative evidence *for this specific small fixture*, not proof that CatBoost's histogram
construction is thread-count-invariant in general. Cross-thread histogram-order
nondeterminism is a real, documented phenomenon in gradient-boosting libraries and is most
likely to surface on larger datasets with more parallel work per node (more rows, more
features, deeper trees) — conditions this 40-row smoke fixture does not create. The
`thread_count: 1` pin is kept regardless: it is cheap, it matches the CLI oracle exactly
(removing the two-oracles-disagree inconsistency the review flagged), and it removes any risk
of this particular hazard reappearing under a future larger fixture or a different CatBoost
version — even though this test found no evidence it currently exists here.
