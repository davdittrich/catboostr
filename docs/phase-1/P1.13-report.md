## 1. What was created

- `.github/workflows/ci.yml` (187 lines) — three jobs:
  1. `build-check`, matrix `[ubuntu-latest, macos-14]` — `R CMD build
     --no-build-vignettes .` then `R CMD check --as-cran` on the resulting
     tarball, failing on any `ERROR` in `00check.log` (grep gate at
     `ci.yml:118-121`).
  2. `integrity` — `prune(fresh acquire) == manifest`
     (`ci.yml:157-164`, via `git diff --exit-code` against the committed
     `tools/vendor/PRUNED_MANIFEST.sha256`) and
     `configure's build-source copy == manifest`
     (`ci.yml:167-183`, via the new `tools/vendor/verify-build-copy.sh`).
  3. Both jobs run `tools/vendor/acquire.sh` and
     `tools/vendor/acquire-thirdparty.sh` first (`ci.yml:96-101`,
     `:150-155`), cached by pinned SHA/key (`ci.yml:84-94`, `:138-148`).
- `tools/vendor/verify-build-copy.sh` (new, 5111 bytes) — hashes every file
  under a given `src-copy` directory against
  `tools/vendor/PRUNED_MANIFEST.sha256`, with one documented exception:
  `configure:144-145` appends an `add_subdirectory(...)` line to the copy's
  `CMakeLists.txt` after copying it, so the script hashes only the
  unmodified prefix (line count taken from the pinned tree) plus a `diff`
  of the appended suffix against the exact string `configure` appends,
  rather than hashing the whole mutated file against the manifest's
  pre-splice hash.

No credentials are used anywhere in the workflow (confirmed by reading
`ci.yml` in full — every step uses only `actions/checkout`,
`r-lib/actions/setup-r*`, `actions/cache`, `apt-get`/`brew`, and repo
scripts).

### 2.1 `configure`'s env-var contract matches the script's assumptions

```
$ grep -n "CATBOOSTR_BUILD_DIR\|CATBOOSTR_VENDOR_SRC\|CATBOOSTR_THIRDPARTY_SRC" configure
127:WORKDIR="${CATBOOSTR_BUILD_DIR:-}"

```

`verify-build-copy.sh:29-30` takes `<src_copy_dir> [vendor_src_dir]`,
consistent with `configure`'s `$WORKDIR/src-copy` layout.

### 2.2 `configure` reaches the build-source copy well before any full compile

```
$ mkdir -p /tmp/.../scratchpad/p113-build
$ timeout 60 env CATBOOSTR_BUILD_DIR=/tmp/.../scratchpad/p113-build CATBOOSTR_JOBS=2 bash configure
[... ragel builds from vendor/thirdparty ...]
make[2]: *** [Makefile:913: ragel-rubyflat.o] Terminated
EXIT: 0
$ ls /tmp/.../scratchpad/p113-build/src-copy
AUTHORS  AWESOME.md  bindings  build  catboost  ...
```

The copy exists well before the 60s bound expired (the timeout killed a
much later `ragel` sub-build step, not the copy itself), confirming the CI
job's 90s bound (`ci.yml:180`) is generous, not tight.

### 2.3 `configure's build-source copy == manifest` — PASS on the real copy

```
$ bash tools/vendor/verify-build-copy.sh /tmp/.../p113-build/src-copy
*** other manifested files (excluding ./CMakeLists.txt): 21887 OK
*** PASS: configure's build-source copy == manifest (modulo the one documented ./CMakeLists.txt splice)
$ echo $?
0
```

`21887 + 1 (CMakeLists.txt, checked separately per §1)` = `21888`, matching
`tools/vendor/PRUNED_MANIFEST.sha256`'s line count exactly.

### 2.4 Perturbation-failure proof — the check is demonstrated failing, not just asserted

```
$ cp src-copy/AUTHORS /tmp/.../AUTHORS.bak
$ echo "PERTURBED" >> src-copy/AUTHORS
$ bash tools/vendor/verify-build-copy.sh src-copy
*** other manifested files (excluding ./CMakeLists.txt): 21886 OK
*** mismatches / missing (excluding ./CMakeLists.txt):
./AUTHORS: FAILED
sha256sum: WARNING: 1 computed checksum did NOT match
*** FAIL: configure's build-source copy does NOT match tools/vendor/PRUNED_MANIFEST.sha256
$ echo $?
1

$ cp /tmp/.../AUTHORS.bak src-copy/AUTHORS
$ bash tools/vendor/verify-build-copy.sh src-copy | tail -3
*** other manifested files (excluding ./CMakeLists.txt): 21887 OK
*** PASS: configure's build-source copy == manifest (modulo the one documented ./CMakeLists.txt splice)
$ echo $?
0
```

Exit code flips `0 -> 1 -> 0` across perturb/revert, proving the check is
load-bearing (would catch a real divergence) and not a vacuous pass.

### 2.5 Vendor tree integrity preserved throughout

Confirmed empty before and after all local validation above — the src-copy
work happened entirely under a scratch directory outside the repo, never
in `vendor/catboost` itself, consistent with `configure:134-136`'s
copy-then-mutate design.
