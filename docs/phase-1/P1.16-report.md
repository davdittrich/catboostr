## 3. `.onLoad` check (Step 3)

New file `R/zzz.R` (fork's own glue; no such file existed before):

```r
.catboost.check_version_skew <- function(pkg_version, compiled_tag) {
  compiled_version <- sub("^v", "", compiled_tag)
  if (nzchar(compiled_version) && compiled_version != pkg_version) {
    stop(.catboost.version_skew_message(pkg_version, compiled_tag), call. = FALSE)
  }
  invisible(TRUE)
}

.onLoad <- function(libname, pkgname) {
  compiled_tag <- tryCatch(.Call("CatBoostVersion_R"), error = function(e) "")
  pkg_version <- as.character(utils::packageVersion(pkgname, lib.loc = libname))
  .catboost.check_version_skew(pkg_version, compiled_tag)
}
```

Design notes:
- Comparison strips the git tag's leading `v` (`ARCADIA_TAG` is `v1.2.10`; `DESCRIPTION`'s
  `Version:` is `1.2.10`) — the only normalization applied; no version-negotiation or
  compatibility matrix, per the ticket's "keep it small" guard.
- An empty compiled tag (build tree not checked out exactly at a tag, e.g. a dev/dirty build) is
  treated as "unknown, not a contradiction" and does not error — deliberate simplification,
  documented here (ponytail: a build with a genuinely different, non-empty tag mismatching
  DESCRIPTION still errors; only the "can't determine" case is silent; upgrade path if ever
  needed: fall back to `ARCADIA_SOURCE_HG_HASH`/commit-based comparison).
- The comparison and message-building logic is factored into
  `.catboost.check_version_skew()`/`.catboost.version_skew_message()`, separate from `.onLoad`
  itself, purely so it is callable directly by the test with independently-chosen inputs (both
  functions are `#' @keywords internal`, not exported — no NAMESPACE change).
