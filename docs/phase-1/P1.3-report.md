# P1.3 — Fork-owned CMakeLists and glue sources

**Status:** DONE. The fork's own `catboostr` CMake target builds against a disposable
copy of the pinned tree, loads into R, registers all 27 entry points exactly once, and
trains + predicts end to end through the real R wrapper functions.

## 1. What was created (fork repo, not vendor/catboost/)

- `src/CMakeLists.txt` — new, fork-authored. `add_shared_library(catboostr)`, linking
  the exact same 17 upstream targets as upstream's own catboostr CMakeLists
  (`vendor/catboost/catboost/R-package/src/CMakeLists.linux-x86_64.txt`, verified working
  by the catboost-8z4.8 spike), plus `target_allocator(... cpp-malloc-mimalloc)`,
  `use_export_script`, and `vcs_info(catboostr)`. Requires a `R_INCLUDE_DIR` cache
  variable (fatal error if unset) — never falls back to
  `vendor/catboost/contrib/libs/r-lang`.
- `src/catboostr.h`, `src/init.c`, `src/catboostr.exports` — byte-identical copies of
  upstream's files (`diff -q` against `vendor/catboost/catboost/R-package/src/{catboostr.h,init.c,catboostr.exports}`
  reports no differences). `init.c` is upstream's own hand-written registrar: one
  `R_registerRoutines(dll, NULL, CallEntries, NULL, NULL)` call, `R_init_libcatboostr`
  matching the NAMESPACE's `useDynLib(libcatboostr, .registration = TRUE)`.
- `src/catboostr.cpp` — copy of upstream's file with **one line changed**: `368`,
  `STRING_PTR` → `STRING_PTR_RO`. Root cause: this machine's real R (4.6.1,
  `/usr/include/R/Rinternals.h`) no longer declares `STRING_PTR` — only
  `STRING_PTR_RO` (a const accessor R introduced to replace it). The one call site is
  read-only (`CHAR(STRING_PTR(...)[i])`, never assigns through the pointer), so the
  rename is behavior-identical, not a workaround. This is real evidence the build used
  R's REAL headers, not the frozen vendored copy — the vendored
  `contrib/libs/r-lang/Rinternals.h` still has the old `STRING_PTR` and would have
  masked this.

No file under `vendor/catboost/` was edited. `git -C vendor/catboost status --porcelain`
is empty (verified before and after).

## 2. Injection method

A disposable copy of `vendor/catboost` (`cp -r`, `.git` stripped) in scratch space.
One line appended to the copy's root `CMakeLists.txt`, after the platform `include()`
chain (which itself runs `add_subdirectory(catboost)` inline, since `include()` is
textual and synchronous):

```
add_subdirectory(/home/dd/Gemini/catboost/src ${CMAKE_BINARY_DIR}/catboostr-fork-build)
```

Two-argument `add_subdirectory(source_dir binary_dir)` lets the fork's real `src/`
directory be built in place — no copying of fork sources into the disposable tree is
needed, and no vendor file is touched to wire it in (only the disposable copy's own
root `CMakeLists.txt`, which is throwaway).

**Target-name collision found and resolved.** Upstream's own
`catboost/R-package/CMakeLists.txt` unconditionally adds
`catboost/R-package/src` (its own `catboostr` target) whenever
`CATBOOST_COMPONENTS` is undefined or contains `R-package`/`R-PACKAGE`. The ticket's
proven invocation passes `-DCATBOOST_COMPONENTS=R-package`, which would define
upstream's `catboostr` target AND the fork's own `catboostr` target in the same CMake
project — a hard configure-time duplicate-target error, not a build hazard. Fix:
`-DCATBOOST_COMPONENTS=R-package-fork` (a value that matches neither
`R-package` nor `R-PACKAGE`). This is a value change only; `catboost/libs` and
`catboost/private` (this target's actual dependencies) are added unconditionally at
the `catboost/CMakeLists.linux-x86_64.txt` level and are unaffected. Configure
succeeded cleanly with this value; the fork's `catboostr` target is the only one
defined.

## 3. Build

Proven invocation, `CATBOOST_COMPONENTS` value adjusted as above, plus
`-DCMAKE_MAKE_PROGRAM=<venv>/bin/ninja` (needed because `ninja` was venv-only, not on
system PATH) and `-DR_INCLUDE_DIR=$(R CMD config --cppflags | sed 's/^-I//')`:

```
cmake -S $SRC -B $BUILD -G Ninja -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_MAKE_PROGRAM=$VENV/bin/ninja \
  -DCMAKE_TOOLCHAIN_FILE=$SRC/build/toolchains/clang.toolchain \
  -DCMAKE_PROJECT_TOP_LEVEL_INCLUDES=$SRC/cmake/conan_provider.cmake \
  -DCMAKE_POSITION_INDEPENDENT_CODE=On \
  -DCATBOOST_COMPONENTS=R-package-fork \
  -DHAVE_CUDA=no \
  -DPython3_EXECUTABLE=$VENV/bin/python -DCYTHON_EXE=$VENV/bin/cython \
  -DR_INCLUDE_DIR=$R_INC
ninja catboostr
```

Configure: `configure_rc=0`. First `ninja catboostr` (cold, 4265 total targets in the
graph): failed at `catboostr.cpp.o` (4264/4265) with the `STRING_PTR` error above.
After the one-line fix, incremental `ninja catboostr`: `[1/2]` recompile,
`[2/2]` link, `build_rc=0`.

Output: `libcatboostr.so`, 34,496,064 bytes, ELF 64-bit x86-64 shared object.
