## 4. Prebuilt-library comparison build (Step 3 precondition — network route)

**Network access confirmed** for the one legitimate purpose the ticket names:

```
$ curl -sI -L https://github.com/catboost/catboost/releases/download/v1.2.10/libcatboostr-linux-x86_64-v1.2.10.so
HTTP/2 302  ... (redirect to release-assets.githubusercontent.com)
HTTP/2 200
last-modified: Thu, 19 Feb 2026 12:38:22 GMT
```

**Method used:** rather than invoking `catboost_download_dynlib()` from `R/install.R`
in-process (that function is unreachable from `configure` per P1.4's report §7 — `configure`
never sources `R/install.R`), the matching v1.2.10 Linux x86_64 asset was fetched directly by
the exact URL that function itself constructs (`base_url/ver/src_dynlib`,
`R/install.R:9-16`), then installed via the fork's own **existing, ticket-independent**
`CATBOOSTR_DEV_BUILD=1` + `CATBOOST_DYNLIB=<path>` route (`configure`, documented and proven
in P1.4's report §4) — the fork's supported "use a pre-existing `.so`" mechanism, which is
exactly route (b)/(a) in P1.4's report §1 upstream inventory. This is the fork's own sanctioned
path for installing against a non-source-built library; it avoids re-deriving
`catboost_download_dynlib()`'s standalone invocation while producing the identical artifact
(same downloaded `.so`) that function would have written.
