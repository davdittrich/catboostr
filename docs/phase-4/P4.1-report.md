## Step 3 — Implementation

**Native glue** (`src/catboostr.cpp`, `.h`, `init.c`, `src/CMakeLists.txt`): four thin wrappers
around the vendor `NCB::` functions, linked via a new `private-libs-quantized_pool_analysis`
target dependency (same target Python's own `_catboost.pyx` links against):
- `CatBoostGetBinarizedStatistics_R` — wraps `GetBinarizedStatistics`, returns a list of
  7-field stat lists (borders/binarized_feature/mean_target/mean_weighted_target/
  mean_prediction/objects_per_bin/predictions_on_varying_feature), cat features first then
  float features (matching the vendor function's own ordering, verified by reading
  `quantized_pool_analysis.cpp:582-618`).
- `CatBoostGetFeatureTypeAndInternalIndex_R` — wraps `GetFeatureTypeAndInternalIndex`.
- `CatBoostCalcCatFeaturePerfectHash_R` — wraps `GetCatFeaturePerfectHash` (returns as
  `REALSXP`, not `INTSXP`: the underlying `ui32` can exceed R's 32-bit signed integer range,
  same convention `CatBoostHashStrings_R` already uses for hash values).
- `CatBoostGetCatFeatureValues_R` — wraps `GetCatFeatureValues`.

All feature-resolution/prediction_type-defaulting/cat-value-to-hash-ordering orchestration
logic lives in R (`R/catboost.R catboost.calc_feature_statistics`), a direct line-by-line port
of `catboost.core.CatBoost.calc_feature_statistics`'s algorithm, calling only these 4 primitives
— matching this fork's established pattern (business logic in R, vendor computation in C++).

**Known, documented R-Pool-architecture limitation** (found while smoke-testing against the
oracle, confidence 95 — read `R/catboost.R:222,410` `CatBoostHashStrings_R` call sites):
`catboost.load_pool()`/`catboost.from_matrix()` pre-hash categorical columns into floats
client-side before the data ever reaches the native `TDataProvider`, unlike Python's `Pool`
(which retains the original strings server-side). So `NCB::GetCatFeatureValues` has nothing to
recover from an R-built Pool's categorical column — `cat_values` defaults to empty unless the
caller supplies `cat_feature_values` explicitly (the same escape-hatch parameter Python's own
docstring documents for exactly this situation). This is not a P4.1 bug: reworking Pool
construction to retain original categorical strings is a Pool-architecture change, out of this
ticket's `Boundary` guard (must not touch `plot_tree`/`catboost.compare`/other P4.x rows or
Pool internals). Documented in the `@param cat_feature_values` roxygen block and the test file's
header comment.

## Fix round — task reviewer finding on commit `bef3b7d`

**Finding (Important):** when `feature` was a plain numeric index (not a name) and
`cat_feature_values` was passed as a plain (non-list) vector, the values were silently dropped.
The normalization block built `cat_feature_values <- setNames(list(cat_feature_values),
as.character(feature))`, keying the lookup by the raw argument (e.g. `"2"`), but
`resolve_feature()` resolves that index to the pool's actual feature name (e.g. `"cat1"`)
whenever `pool_feature_names` is non-empty — the normal case. The later
`cat_feature_values[[fname]]` lookup (`fname = "cat1"`) then missed, silently falling back to
`.Call("CatBoostGetCatFeatureValues_R", ...)`, which returns empty for R-built pools (the
documented pre-hashed-categorical-columns limitation, Step 3 above). Net effect: caller-supplied
values vanished with no error for a documented, supported call pattern. Not exercised by either
existing test (both used `feature = "cat1"`, a name, not an index).

**Root cause:** the plain-vector-to-named-list normalization ran *before* feature resolution,
keyed by the unresolved raw argument.

**Fix:** deferred the normalization. `R/catboost.R`: the plain vector is now held aside in
`plain_cat_feature_values` (not converted to a named list immediately); after the
`resolve_feature()` loop determines the actual resolved name (`feature_names_out[1]` — safe
because this path only runs when `single_feature` is `TRUE`, i.e. exactly one feature), it is
inserted into `cat_feature_values` keyed by that resolved name, before the native call. No
other logic changed.

**Covering test:** added
`"calc_feature_statistics: numeric feature index + plain-vector cat_feature_values matches
Python oracle"` to `tests/testthat/test_calc_feature_statistics.R` — calls
`catboost.calc_feature_statistics(model, pool, feature = <0-based index of "cat1">,
cat_feature_values = inputs$cat1)` (index, not name; plain vector, not a list) and asserts the
result matches the same `expected$single_cat` oracle fixture the existing name-keyed test uses.
