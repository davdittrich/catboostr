## Step 1 — Python oracle introspection

`CatBoost.compare(self, model, data, metrics, ntree_start=0, ntree_end=0, eval_period=1,
thread_count=-1, tmp_dir=None, plot_file=None, log_cout=None, log_cerr=None)`
(`catboost/python-package/catboost/core.py:3283`). Source shows `compare()` itself only
draws an interactive Jupyter widget and returns `None` — its real computation is two calls,
`self._eval_metrics(...)` and `model._eval_metrics(...)`, on the same `data`/`metrics`
(core.py:3345-3349), each landing in the same `_base_eval_metrics` → `TMetricsPlotCalcer`
C++ path (`catboost/libs/metrics`) that the public `eval_metrics()` wrapper
(core.py:3234) also uses and documents as returning `dict: metric -> array`. Per the task
brief's Reference Data note and spec §4.3's "Structural" row, the comparable/testable
surface is this underlying metrics-diff data structure, not the widget rendering.

## Step 2 — R signature design / native-glue gap check

`grep -n "^catboost\.\w* <- function" R/catboost.R` showed `catboost.eval_metrics(model,
pool, metrics, ntree_start, ntree_end, eval_period, thread_count, tmp_dir)` already exists
(R/catboost.R:3387), calling the native `CatBoostEvalMetrics_R` glue
(`src/catboostr.cpp:2111`) — the same vendor `TMetricsPlotCalcer` entry point Python's
`eval_metrics()`/`compare()` use, returning a named list (metric -> numeric vector). No new
native glue was needed: `catboost.compare` is a plain R wrapper calling
`catboost.eval_metrics()` once per model. New R signature (append-only, no existing
signature touched), named `catboost.compare` and not `model.compare` (per the brief, to
avoid colliding with `predict.catboost.Model`'s S3 dispatch):

```r
catboost.compare(model, other, pool, metrics, ntree_start = 0L, ntree_end = 0L,
                  eval_period = 1, thread_count = -1, tmp_dir = NULL)
```

Returns `list(model = <eval_metrics result>, other = <eval_metrics result>)` with class
`"catboost.compare"`.

## Step 3 — Oracle fixture + structural differential test

`tools/oracle/gen_compare_fixture.py` trains two `CatBoostClassifier` models (depth 2 vs
depth 4, different seeds) on the same 20-row synthetic pool, then calls
`model.eval_metrics(pool, ["Logloss", "AUC"], ntree_start=0, ntree_end=0, eval_period=1)`
on each — the exact same call shape `compare()` makes internally for each side — and pins
both dicts to `tests/fixtures/oracle/compare.json`.

`tests/testthat/test_compare.R` builds the matching R pool/models via
`catboost.load_pool()` / `catboost.train()`, calls `catboost.compare(model, other, pool,
metrics)`, and asserts (a) `expect_s3_class(result, "catboost.compare")`, (b) each of
`result$model`/`result$other`'s per-metric numeric vectors match the oracle fixture within
`tolerance = 1e-6`, plus five `expect_error()` cases for `model`/`other`/`pool`/`metrics`
being `NULL` and `other` not being a `catboost.Model`.
