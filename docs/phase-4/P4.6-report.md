## Step 1 — Python oracle signature and source (pinned catboost 1.2.10, `tools/oracle/.venv`)

```
SIGNATURE: (model, data, thread_count=-1, plot=False)
```

Docstring: "Build points of ROC curve." Returns `(fpr, tpr, thresholds)`. Body validates
`data` is a `Pool` or list of `Pool`s, then delegates entirely to the native
`_get_roc_curve(model._object, data, thread_count)` binding
(`catboost/python-package/catboost/_catboost.pyx:6744`):

```cython
cpdef _get_roc_curve(model, pools_list, int thread_count):
    thread_count = UpdateThreadCount(thread_count)
    cdef TVector[TDataProviderPtr] pools
    for pool in pools_list:
        pools.push_back((<_PoolBase>pool).__pool)
    cdef TVector[TRocPoint] curve = TRocCurve(
        dereference((<_CatBoost>model).__model), pools, thread_count
    ).GetCurvePoints()
    tpr = np.array([1 - point.FalseNegativeRate for point in curve])
    fpr = np.array([point.FalsePositiveRate for point in curve])
    thresholds = np.array([point.Boundary for point in curve])
    return fpr, tpr, thresholds
```

`TRocCurve` lives in `catboost/private/libs/algo/roc_curve.{h,cpp}`. Its
`TDataProviderPtr`-constructor path applies the model to each pool to get raw
approxes, converts them to `Probability`-space via `PrepareEval`, then calls
`BuildCurve`, which:

1. Rounds each label to `{0, 1}` (`target = labels[i] + 0.5` truncated to int).
2. Stable-sorts documents by probability, descending.
3. Sweeps once, emitting a `(Boundary, FalseNegativeRate, FalsePositiveRate)` point
   at every probability change, starting at `(1, 1, 0)` and ending at `(0, 0, 1)`.
4. `AddPoint` inserts a synthetic intersection point whenever the running FPR/FNR
   curves cross (linear interpolation between the two adjacent points), so the
   output curve is monotone and free of the "staircase overshoot" a naive sweep
   would produce.

Confidence: 100 (direct reads of `_catboost.pyx:6744`, `roc_curve.h`, `roc_curve.cpp`).

## Step 3 — R implementation

`R/catboost.R` — `catboost.get_roc_curve(model, pool)` (new function, exported in
`NAMESPACE`). Accepts a single `catboost.Pool` or a list of pools (matching the
Python signature's `data` parameter); no new native (`src/catboostr.cpp`) glue —
reuses `catboost.predict(model, p, prediction_type = "Probability")` (already
applies the same `PrepareEval`-equivalent sigmoid transform the C++ engine's
`TRocCurve` constructor uses internally) and `catboost.pool.get_label(p)`. The
curve sweep (label rounding, stable descending sort, `AddPoint` intersection
insertion) is a direct line-for-line port of `BuildCurve`/`AddPoint`
(`roc_curve.cpp`), computed natively in R — no CLI subprocess at runtime, per
Constraint III ("R computes natively, CLI run only as oracle for comparison").

Returns `list(fpr, tpr, threshold)` (named, not the Python tuple order, since R
list access is by name) — `threshold` singular to match the CLI's TSV header
casing convention used elsewhere in this port style.

Boundary scope respected: `catboost.utils.get_fnr_curve`, `get_fpr_curve`,
`select_threshold`, and all other `catboost.utils.*` rows are out of scope and
not touched; `plot=` (matplotlib rendering) is not implemented — no ticket line
requires it and no test exercises it (`ponytail`: skipped, add if a future ticket
names `plot=` explicitly).
