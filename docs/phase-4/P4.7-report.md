## Step 3 — Design decision: in process, not a subprocess wrapper

The ticket allowed a clean subprocess wrapper around the pinned CLI binary **if no
in-process equivalent exists**. One does exist, and it is already linked:

- The CLI mode is a thin driver. `vendor/catboost/catboost/app/mode_eval_feature.cpp`
  parses flags, reads the dataset, applies three guards, and then calls one core function:

  ```cpp
  const auto featureEvalSummary = EvaluateFeatures(
      catBoostFlatJsonOptions,
      featureEvalOptions,
      /*objectiveDescriptor*/Nothing(),
      /*evalMetricDescriptor*/Nothing(),
      poolLoadParams.CvParams,
      pools.Learn
  );
  ```

- `EvaluateFeatures` is declared in `catboost/libs/train_lib/eval_feature.h` and built from
  `catboost/libs/train_lib/eval_feature.cpp`, a source file of the
  `catboost-libs-train_lib` target
  (`vendor/catboost/catboost/libs/train_lib/CMakeLists.linux-x86_64.txt`).
- `catboost-libs-train_lib` is **already** linked into the `catboostr` target
  (`src/CMakeLists.txt`), because `CatBoostCV_R` needs `CrossValidate` from the same
  library. So the in-process route adds **no new link dependency and no CMake change** —
  the symbol was already in `libcatboostr.so`, merely unused.

This also matches the precedent this repo already set for a CLI-only mode: P3.3 linked
`catboost-libs-dataset_statistics` and called
`NCB::CalculateDatasetStatisticsSingleHost` directly rather than shelling out
(comment in `src/CMakeLists.txt`).

A subprocess wrapper would have been strictly worse on every ranked criterion in the
"Mechanism Justification" order: it needs a 287 MB binary present at runtime (it is
gitignored and CI does not have it), it pays process spawn + dataset re-read + re-parse per
call, it can only return the CLI's ~10-significant-digit text, and it needs temp-file,
cleanup and stderr-propagation code that the in-process call does not. **Decision:
in process.** Rejected alternative recorded here rather than silently skipped, per the
ticket.

Confidence: 100 (read of `mode_eval_feature.cpp`, `eval_feature.h`, both `CMakeLists`).

## Step 4 — Implementation

**Native (`src/catboostr.cpp`, `src/catboostr.h`, `src/init.c`).**
`CatBoostEvaluateFeatures_R` takes the fit params JSON, the pool handle, and the eight
mode-specific arguments; builds `NCatboostOptions::TFeatureEvalOptions`; re-applies the two
dataset-dependent guards `mode_eval_feature.cpp` applies before calling the core (tested
feature index in range; all tested feature sets distinct); passes a default-constructed
`TCvDataPartitionParams`, which is what the CLI passes when `--cv` is absent — the fold
layout then comes from `featureEvalOptions` (`eval_feature.cpp:1181`); calls
`EvaluateFeatures`; and converts `TFeatureEvaluationSummary` to a named R list.

The returned list mirrors the columns of the CLI's `--feature-eval-output-file` TSV, which
`ToString(TFeatureEvaluationSummary)` (`eval_feature.cpp:58`) builds from exactly these
fields:

| R list element | Summary field | CLI TSV column |
| :--- | :--- | :--- |
| `p_value` | `WxTest` | `p-value` |
| `best_iterations` | `BestBaselineIterations` | `best iteration in each fold` |
| `metric_names` | `MetricNames` | (the per-metric column headers) |
| `metric_delta` | `AverageMetricDelta` | one column per metric |
| `feature_sets` | `FeatureSets` | `feature set` |

R keeps the integer lists as integer vectors and the deltas at full double precision; the
CLI can only comma-join and round them. That is a strict superset of the TSV, not a
divergence.

**R (`R/catboost.R`).** `catboost.eval_feature(pool, features_to_evaluate = list(),
params = list(), eval_mode = "OneVsNone", offset = 0, fold_count = 3,
fold_size_unit = "Object", fold_size = 0, relative_fold_size = 0,
timesplit_quantile = 0.5)`. Naming follows §4.2's rule (`verb_object` snake_case, never a
dotted name) and the defaults are the C++ `TFeatureEvalOptions` constructor defaults
(`feature_eval_options.cpp`), except `fold_count`, which follows `catboost.cv`'s R-side
default of 3 rather than the C++ `0` that `EvaluateFeatures` rejects outright
(`CB_ENSURE(foldCount > 0, ...)`). Calling convention (pool first, `params` list,
`prepare_train_export_parameters`) copies `catboost.cv` exactly.

**Fixture (`tools/oracle/cli/gen_eval_feature_fixture.sh`,
`tests/fixtures/oracle-cli/eval_feature_summary.tsv`,
`tests/fixtures/oracle-cli/eval_feature_metadata.json`).** Follows the established CLI
oracle pattern: a committed generator script beside `gen_smoke_fixture.sh`, reusing the
same 40-row `smoke_data.csv` / `smoke.cd` every other CLI fixture uses, and a metadata JSON
in the shape of `smoke_metadata.json`. One documented deviation: it does **not** pipe
through `tsv_to_json.py`. That converter is written for `calc`'s all-numeric TSV and would
turn `best iteration in each fold` into a string when it holds `19,7` but an int when it
holds a single value; the raw TSV is committed instead, which is lossless and byte-exact.
The script runs the mode twice into separate train-dirs and **fails** if the two summaries
differ, so a non-deterministic fixture can never be committed.

## Fix round 1 — missing "tested feature must not be ignored" guard

### Finding as reported (blocking, task review of `e6ab0fb`) — confirmed

`mode_eval_feature.cpp:89-95` applies three dataset-dependent guards before calling
`EvaluateFeatures`; the first commit ported only two. The missing one:

```cpp
CB_ENSURE(Count(poolLoadParams.IgnoredFeatures, feature) == 0,
          "Tested feature " << feature << " should not be ignored");
```

It is reachable from R and it is a wrong-result bug, not a cosmetic one:

- `poolLoadParams.IgnoredFeatures` is filled from the ordinary `ignored_features`
  *training* option, not a mode-specific flag — `CopyIgnoredFeaturesToPoolParams`
  (`mode_eval_feature.cpp:63`) sets it via `GetOptionIgnoredFeatures`
  (`private/libs/app_helpers/bind_options.cpp:54-61`). `catboost.eval_feature`'s `params`
  argument feeds that same option, so R users reach the exact input the CLI rejects.
- The core does not re-check it: `UpdateIgnoredFeaturesInLearn` (`eval_feature.cpp:567`)
  simply drops the feature, so the run would report a p-value and metric delta for a
  feature that was absent from every model it trained.

### Second defect found while fixing it (not in the review, same root)

Writing the regression test made the first commit fail with an unrelated error:

```
Error: catboost/private/libs/options/json_helper.h:41:
  Can't parse parameter "ignored_features" with value: ["2"]
```

`EvaluateFeatures` is **the one core entry point that does not resolve feature names and
string indices in `ignored_features` itself**. `TrainModel` (`train_model.cpp:1628`) and
`CrossValidate` (`cross_validation.cpp:359,569`) each call
`ConvertIgnoredFeaturesFromStringToIndices(metaInfo, &plainJsonParams)` internally; for
`eval-feature` the CLI mode does it externally instead (`mode_eval_feature.cpp:50`), and
the first commit did not reproduce that step. Since `prepare_train_export_parameters`
always serialises `ignored_features` as an array of strings
(`I(as.character(...))`, `R/catboost.R:2655`), **every** `ignored_features` value — not
only clashing ones — made `catboost.eval_feature` die in the option parser, while
`catboost.train` and `catboost.cv` accepted the identical value. Demonstrated directly:

```
$ Rscript -e '... prepare_train_export_parameters(list(ignored_features = 2)) ...'
{"ignored_features":["2"]}
$ Rscript -e '... catboost.train(p, params = list(iterations = 2, ignored_features = 2)) ...'
CatBoost model (2 trees)
Loss function: RMSE
Fit to 2 feature(s)
```

### Fix

Both defects are one root cause — the CLI mode's pre-call preparation was not fully
reproduced — so both are fixed there, natively, in `CatBoostEvaluateFeatures_R`:

1. `ConvertIgnoredFeaturesFromStringToIndices(pool->MetaInfo, &fitParams)` immediately
   after `LoadFitParams`, mirroring `mode_eval_feature.cpp:50`.
2. The missing `CB_ENSURE`, applied against the **converted** indices (read back with
   `TJsonFieldHelper<TVector<ui32>>::Read`, the same helper the option parser uses), with
   the CLI's own wording.

Doing it natively rather than R-side is both smaller and more correct: after the converter
runs, `ignored_features` is already canonical `ui32` indices, exactly the state the CLI's
guard sees. An R-side check would have had to re-implement name resolution — and an
attempted R-side version did exactly that and got it wrong, because
`catboost.pool.get_feature_names()` returns `"" "" "cat1"` for this fixture (only `cat1`
is named in `smoke.cd`), so name lookup silently missed. The native converter resolves
names, `#tag` references and index ranges the same way for every entry point.

Also taken from the same review's non-blocking notes: explicit R-side `offset >= 0` and
`fold_count >= 1` guards, so a negative `offset` gives a readable R error instead of
wrapping to a huge `ui32`.
