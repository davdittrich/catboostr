# P5.1: init_model support (continue training) — catboost-8z4.58

## 1. Python oracle behavior (quoted)

`catboost/python-package/catboost/core.py:5525` (docstring on `CatBoostClassifier.fit`,
identical wording at `:2878` for `CatBoost.fit` and `:6157` for `CatBoostRegressor.fit`):

```
init_model : CatBoost class or string or os.PathLike, [default=None]
    Continue training starting from the existing model.
    If this parameter is a string or os.PathLike, load initial model from the path specified by this string.
```

`core.py:2675-2679` shows path/string handling in `CatBoost.fit`:

```python
if (init_model is not None) and isinstance(init_model, PATH_TYPES):
    try:
        init_model = CatBoost().load_model(init_model)
    except Exception as e:
        raise CatBoostError("Error while loading init_model: {}".format(e))
```

`_catboost.pyx:5479` (`_CatBoost._train`) passes it straight through to the vendor's
`TrainModel()` free function (`catboost/libs/train_lib/train_model.h:153`) as
`TMaybe[TFullModel*] initModel` — the exact same overload `src/catboostr.cpp`'s
`CatBoostFit_R` already called (previously always with `Nothing()`).

## 2. What was implemented

- `src/catboostr.h` / `src/catboostr.cpp`: `CatBoostFit_R` gained a 4th `SEXP
  initModelParam` argument (appended last, so no existing positional 3-arg semantics
  changed — the R wrapper is the only caller and now always passes 4 args). When not
  `R_NilValue`, it is cast to `TFullModelHandle` (`TFullModel*`) and passed as
  `TMaybe<TFullModel*> initModel` to the vendor's `TrainModel()` — the identical call
  Python makes. `src/init.c`'s `.Call` registration arity was bumped 3 → 4.
- `R/catboost.R`: `catboost.train(learn_pool, test_pool = NULL, params = list(),
  init_model = NULL)`. New trailing argument, default `NULL`, so every existing
  positional/named call site is unaffected. Accepts a `catboost.Model` object or a
  string/path (loaded via the existing `catboost.load_model`, matching Python's
  `PATH_TYPES` handling). The model's handle is rehydrated via the existing
  `catboost.restore_handle` helper (same pattern already used before every other
  `.Call` that needs `model$cpp_obj$handle`) before its raw pointer is threaded into
  the native call.
- `man/catboost.train.Rd`: regenerated content for the new `init_model` argument
  (hand-applied — see note in Self-review below on why roxygen2's own pipeline
  couldn't be driven end-to-end in this environment).
- No `catboost.cv` changes: Python's `cv()` (`core.py:7023`) has no `init_model`
  parameter, so there is nothing to mirror there — the Definition-of-Done bullet is
  about non-regression, verified below.
- `initLearnProgress` is deliberately left `nullptr`, matching the CLI's own usage of
  this same free-function overload: `TrainModel()` reconstructs learn progress from
  `initModel` internally when the cache pointer is null. Python additionally caches
  `TLearnProgress` across calls on the same `_CatBoost` object for speed; that caching
  is a performance-only optimization on top of correctness, not part of the
  continuation mechanism itself, and is out of scope here ("reuse, do not reimplement
  training-continuation logic").

## 3. Tests

- `tools/oracle/gen_init_model_fixture.py`: generates
  `tests/fixtures/oracle/init_model.json` by training a base RMSE model on rows 0-7
  of a 16-row synthetic dataset, then continuing training on rows 8-15 via
  `CatBoost.fit(init_model=base_model)`. Pins predictions and tree counts.
  `base_tree_count=10`, `continued_tree_count=15` (10 base + 5 continuation
  iterations — proves trees actually accumulate, not just that training "succeeds").
- `tests/testthat/test_init_model.R`:
  - Differential test: R's continued-model `RawFormulaVal` predictions vs. the Python
    oracle's, tolerance `1e-6`, matching the fixture's `1e-06` disposition-matrix
    tolerance.
  - Tree-count accumulation check against the oracle's counts.
  - `init_model` accepts a file path (string), not just a `catboost.Model` object.
  - Invalid `init_model` type raises a clear error.
  - Backward-compat regression: `catboost.train(pool, NULL, params)` (pre-existing
    3-positional-arg call shape, no `init_model`) reproduces the same base-model
    predictions/tree-count as before — proves the new argument doesn't perturb
    existing call sites.

## 7. Fix round (review finding)

**Finding:** differential test used `tolerance = 1e-6`; spec §4.3's default for
Python-oracle comparisons is `1e-12`, and a `1e-6` override requires a
`tolerance_justification` in the matrix, which was left empty.

**Fix:** tried `1e-12` first (option (a)) — all 5 `expect_equal` calls in
`tests/testthat/test_init_model.R` tightened from `1e-6` to `1e-12` and it passes
cleanly (predictions and tree counts match the oracle bit-for-bit at that
tolerance), so the spec default applies as-is, no justification override needed.
`tests/fixtures/parity/matrix.dispositioned.json`'s `param:init_model.tolerance`
updated `1e-06` → `1e-12` to match.
