## 2. `mode_metadata.cpp` source (authoritative behavior, read from `vendor/catboost/catboost/app/mode_metadata.cpp`)

- `set`: `params.Model.ModelInfo[key] = value;` then re-exports the model (in place, or to `-o`).
- `get`: for each `--key`/free-arg, prints `key\tModelInfo[key]` (Plain; `operator[]` default-constructs `""` for a missing key) or a JSON object (JSON format).
- `dump`: iterates the **entire** `ModelInfo` map, same Plain/JSON output.
- `dump-feature-names`: `Cout << "Feature names: " << JoinSeq("\t", GetModelUsedFeaturesNames(params.Model));` (Plain) or `{"feature_names": [...]}` (JSON) — reads `TFullModel`'s used-feature names, **not** `ModelInfo`.

`TFullModel::ModelInfo` is `THashMap<TString, TString>` (`catboost/libs/model/model.h:660`).

## 3. Python oracle source (`vendor/catboost/catboost/python-package/catboost/core.py:2061-2062`, `_catboost.pyx:5875-5879,6157-6207`)

```python
def get_metadata(self):
    return self._object._get_metadata_wrapper()   # -> _MetadataHashProxy(self)

def feature_names_(self):
    return self._object._get_feature_names() if self.is_fitted() else None
    # _get_feature_names(self): return [to_str(s) for s in GetModelUsedFeaturesNames(dereference(self.__model))]
```

`_MetadataHashProxy` (`_catboost.pyx:6157`) is a dict-like view directly onto `model->ModelInfo`:
`__getitem__` raises `KeyError` for a missing key, `.get(key, default)` returns the default,
`__setitem__` mutates `ModelInfo` in place, `__delitem__`/`keys`/`items`/`__iter__`/`__len__` round it out.
There is **no** separate top-level `set_metadata` function — Python's calling convention is
`model.get_metadata()[key] = value` on the proxy returned by `get_metadata()`.

`CatBoost`/`CatBoostClassifier`/`CatBoostRegressor`/`CatBoostRanker.get_metadata` all resolve to this
same `_CatBoostBase._object._get_metadata_wrapper()` — one accessor, four exposure points.

## 4. What was implemented

**Native (`src/catboostr.cpp`, `src/catboostr.h`, `src/init.c`, `src/catboostr.exports` — this project's own
editable R-package sources, not `vendor/catboost/`):**

- `CatBoostGetModelInfo_R(modelParam)` — returns a named `STRSXP` of every `ModelInfo` key/value pair
  (mirrors the CLI's `metadata dump` and Python's `dict(get_metadata())`).
- `CatBoostSetModelInfo_R(modelParam, keyParam, valueParam)` — `model->ModelInfo[key] = value;` in place
  (mirrors the CLI's `metadata set` and Python's `get_metadata()[key] = value`).
- `CatBoostGetModelUsedFeatureNames_R(modelParam)` — wraps `GetModelUsedFeaturesNames()` (mirrors the CLI's
  `metadata dump-feature-names` and Python's `model.feature_names_`).

**R (`R/catboost.R`, exported via `NAMESPACE`, hand-written `.Rd` in `man/` — roxygen2's doc pipeline
crashes in this environment, confirmed by re-running `roxygen2::roxygenize(".", roclets="rd")`, which fails
inside `pkgbuild::compile_dll` with `Error in ... System command 'R' failed`; `.Rd` files were hand-edited to
match what roxygen2 would generate from the `@name`/`@title`/`@param`/`@return`/`@description` roxygen
comments, per the pre-existing note for this environment):**

- `catboost.get_metadata(model)` — named character vector of all metadata key/value pairs.
  `catboost.get_metadata(model)[["key"]]` errors on a missing key (`subscript out of bounds`), matching
  Python's `KeyError`; `catboost.get_metadata(model)["key"]` returns `NA`, matching `.get(key)`.
- `catboost.set_metadata(model, key, value)` — single-key/value in-place mutation (validates both are
  length-1 character).
- `catboost.get_model_feature_names(model)` — character vector of feature names, falling back to the
  bare index for unnamed features (same rule as the CLI's `GetModelUsedFeaturesNames`).

**Params-validation gate check:** none of the three new functions touch a `params`-shaped list — they
operate directly on the model handle — so `validate_params_keys()`/`process_synonyms()` (wired into
`catboost.train`/`catboost.cv`) never sees them and there is nothing to interact with (verified by reading
`process_synonyms()`'s call sites; these functions aren't among them).

### CLI subcommand -> R function mapping (all four have an in-process equivalent; none needed a CLI-only shim)

| CLI subcommand | R function | Python equivalent |
| --- | --- | --- |
| `metadata set` | `catboost.set_metadata()` | `model.get_metadata()[key] = value` |
| `metadata get` | `catboost.get_metadata()[[key]]` | `model.get_metadata()[key]` / `.get()` |
| `metadata dump` | `catboost.get_metadata()` | `dict(model.get_metadata())` |
| `metadata dump-feature-names` | `catboost.get_model_feature_names()` | `model.feature_names_` |

## 5. Differential tests (`tests/testthat/test_metadata.R`)

Two fixtures, regenerated by the commands documented in the test file's header:

- `tests/fixtures/oracle/metadata.json` (Python oracle, `tools/oracle/gen_metadata_fixture.py`): a
  20-row synthetic `CatBoostClassifier` fit (same recipe as `gen_roc_curve_fixture.py`), capturing
  `get_metadata()` before/after a `["custom_key"] = "custom_value"` set, `.get()` on a missing key, and
  `feature_names_`.
- `tests/fixtures/oracle-cli/metadata_dump.json` (CLI oracle, pinned `catboost-v1.2.10`): `metadata dump`
  (`--dump-format JSON`, needed because the CLI's Plain format breaks on `catboost_version_info`'s embedded
  newlines), `metadata dump-feature-names`, and a `metadata set --key custom_key --value custom_value`
  followed by `metadata get --key custom_key` on the same smoke-fixture model used by every other
  `oracle-cli` test.

26 assertions across both sections cover: key-set parity, byte-identical deterministic fields
(`class_params`, `training` metrics — proving cross-language bit-exact determinism extends to the
metadata block), `params`/`output_options` parity up to their one run-specific field (`train_dir`),
`feature_names_`/`dump-feature-names` parity, the `[[`-errors-vs-`[`-returns-NA missing-key contract,
argument validation, non-`catboost.Model` rejection, and the `set` + subsequent `get` round trip against
both oracles (the CLI-oracle `mode:metadata set` row's disposition note explicitly calls for exactly this:
"state-mutator; parity via a subsequent metadata get").

Three categories of known, non-metadata-accessor divergence are excluded from strict comparison and
documented in the test file's header comment (not swept under the rug):

- `train_finish_time`/`model_guid`: embed wall-clock time / a fresh GUID on every serialization
  (previously documented in `docs/phase-0/catboost-8z4.3-report.md`: `.cbm` files are not byte-identical
  across runs even with identical training data/params/seed).
- `catboost_version_info`: baked in at compile time from the *building* tree's VCS info; this R package's
  build tree has none (compiled from a gitignored acquired copy of `vendor/catboost`, not a git checkout),
  so it reads "No VCS" locally versus the pinned CLI/Python wheel's real git commit info.
- CLI-section only: `class_params`'s `class_label_type` (CLI's raw-CSV `fit` treats the Label column as a
  String class label; `catboostr`'s label ingestion normalizes numeric-looking labels to Integer before
  they reach the C++ core) and `flat_params.model_format` (only set when training writes straight to a file
  via an explicit CLI flag; `catboost.train()` keeps the model in memory). Both are pool/label-ingestion or
  file-vs-memory training-path differences, already out of this ticket's scope ("metadata mode only — no
  normalize-model").

## 9. Self-review findings / concerns

- `catboost.get_metadata(model)[["key"]]` erroring on a missing key (rather than returning `NA`) is a
  deliberate design choice to match Python's `KeyError`, documented in both the roxygen comment and the
  `.Rd` file; `[ ]` single-bracket indexing is the `NA`/`.get()`-style alternative. Flagging this explicitly
  since it's a slightly unusual R idiom (most R accessors here return `NA`/`NULL` rather than erroring).
- `catboost.get_model_feature_names` is a new name, not literally `catboost.get_feature_names`, chosen to
  disambiguate from the existing `catboost.pool.get_feature_names` (Pool-level, unrelated function).
- `git -C vendor/catboost status --porcelain` is empty — zero vendor writes, confirmed after all edits.
- Not implemented, and not needed: no CLI-only shim, since all four CLI subcommands have an in-process
  Python-equivalent-backed R function (see mapping table above).
