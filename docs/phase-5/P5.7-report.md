`mode_normalize_model.cpp` (`catboost/app/`) logic (read; confidence 100):

- Reads the model, prints `Input model scale <S> bias <B>` if
  `--print-scale-and-bias`.
- If `-i/--input-path` pools given: `CB_ENSURE(!Scale.Defined() &&
  !Bias.Defined(), "Conflicting options: -i and --set-scale/bias")`; resets
  scale/bias to `{1.0, {}}`, computes `approx = CalcMinMaxOnAllPools(model,
  ...)` (min/max raw prediction over the pool(s)), `CB_ENSURE(approx.Min !=
  approx.Max, "Model gives same result on all docs")`, then `scale = 1.0 /
  (approx.Max - approx.Min)`, `bias = -scale * approx.Min`. **This branch has
  no Python `get_scale_and_bias`/`set_scale_and_bias` equivalent** -- it is a
  CLI-only auto-normalization capability.
- Else: `scale = --set-scale ?? current`, `bias = --set-bias ?? current`.
- If the resulting scale/bias differ from the input, or `--output-model` was
  given, writes the model out (`ExportModel`), printing `Output model scale
  <S> bias <B>` first if `--print-scale-and-bias`.

## 4. Capability mapping (confidence 95)

- `--set-scale`/`--set-bias`/`--print-scale-and-bias` map 1:1 onto
  `set_scale_and_bias`/`get_scale_and_bias` -- same struct, same semantics.
- `-i/--input-path` (auto min-max normalization) is **CLI-only**: no Python
  method computes scale/bias from a pool's prediction range. Implemented as
  an R-side composition (`catboost.normalize_model_from_pool`, R/catboost.R)
  that reimplements `CalcMinMaxOnAllPools` + the `SetScaleAndBias` call using
  only existing R primitives (`catboost.predict(..., prediction_type =
  "RawFormulaVal")`, `catboost.set_scale_and_bias`) -- no new C++ binding
  needed for this branch. Verified against the CLI oracle at relative 1e-9
  per §III's CLI-only-residual tolerance.
- `--output-model`/`mode:normalize-model` (file-to-file roundtrip): exercised
  via `catboost.save_model()`/`catboost.load_model()` preserving scale/bias
  set via `catboost.set_scale_and_bias()`.

- No `vendor/catboost/` writes: `git -C vendor/catboost status --porcelain`
  is empty.
- No core patches: all new code is in `src/catboostr.*` (append-only R
  package glue), `R/catboost.R` (append-only), and test/tool files.
- Tolerances: Python-oracle rows at 1e-12 (`PY_TOL`), CLI-oracle rows at 1e-9
  (`CLI_TOL`), matching §III exactly -- including the `-i` CLI-only-residual
  row.
- `.Rd` files hand-written (roxygen2 crashes in this environment, per prior
  phase reports) but structurally match what roxygen2 would generate from
  the `R/catboost.R` doc comments (`\name`, `\alias`, `\usage`, `\arguments`,
  `\value`, `\description` in the standard order/wording).
- Bias-vector collapsing: Python's `_get_scale_and_bias` collapses an empty
  bias to `0` and a length-1 bias to a bare scalar; R's
  `CatBoostGetScaleAndBias_R` always returns the full `TVector<double>` as an
  R numeric vector (no ambiguity to paper over in R). Tests compare via
  `expect_equal(sb$bias, expected$bias_before, ...)`, which works for both
  representations since R recycles/coerces length-1 vectors transparently in
  `all.equal`-based comparison; verified directly (assertion 1 of test 1
  passes against the Python fixture's scalar `bias_before`).
- Multi-dimensional bias (list-bias branch, `core.py:2428-2429`, e.g.
  multiclass models) is **not exercised** by the differential test -- the
  RMSE regression oracle model has `ApproxDimension == 1`, and passing a
  bias vector of length != ApproxDimension raises `CatBoostError` in the
  Python oracle itself (confirmed: `set_scale_and_bias(1.5, [0.3, -0.2])` on
  the single-target model raised `"Inappropriate dimension of bias, should
  be 1 found 2"`). The R `CatBoostSetScaleAndBias_R` binding is
  dimension-agnostic (accepts any-length bias vector; the underlying
  `TFullModel::SetScaleAndBias` doesn't validate dimension at that layer),
  but no oracle-verified multi-dimensional test exists. Not a matrix-row gap
  (no matrix row specifically requires multiclass coverage), flagged here
  for visibility.
