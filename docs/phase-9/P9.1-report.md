## 1. Method

546 red rows were partitioned by `kind` (flag 217, method 158, class 38,
function 36, property 36, enum_member 22, parameter 19, attribute 11, mode 9)
and classified row-by-row, never by sampling-and-extrapolating:

- `flag`/`parameter`/`mode` (245 rows): classified directly against
  `tests/fixtures/parity/closure_overlay.json`'s existing per-row evidence
  (GPU-only native errors, build-metadata universal flags, `--dev-*`
  internal flags) plus the ticket's own explicit strong-candidate lists.
- `class`/`function`/`attribute`/`enum_member` (117 rows) and the 158
  `method` + 36 `property` rows (194 rows, dominated by the 4-class
  sklearn fan-out CatBoost/CatBoostClassifier/CatBoostRegressor/CatBoostRanker):
  two independent research passes read the actual pinned CatBoost Python
  source (`tools/oracle/.venv/lib/python3.14/site-packages/catboost/{core,
  utils,eval}.py`) and `R/catboost.R`/`tests/testthat/*.R` line-by-line for
  every ambiguous row rather than trusting names. Their evidence is folded
  into the per-row `tolerance_justification` written to
  `closure_overlay.json` for every bucket-A/B row (see the overlay diff for
  full citations — file:line references throughout).

Bucket test applied throughout (spec, this ticket's own guard): a row is
**out-of-scope (A)** only if it is not a CatBoost capability at all —
Python-language plumbing, build metadata, or a re-export duplicate — never
merely because implementing it would take effort. **GPU-deferred (B)**
requires concrete evidence of a GPU-only code path on this CPU-only host.
Everything else is **real gap (C)** and was left red (no overlay entry per
the ticket's own rule: bucket C is Phase 10's input, not this ticket's to
touch).

Two corrections the evidence produced against my own first-pass guesses,
worth recording because they show the "read the source" rule doing real
work: `plot_partial_dependence`/`plot_predictions` looked like
matplotlib-only visualization (a plausible bucket-A pattern, and this
project's own precedent for `catboost.compare()`'s widget) but
`core.py:3847-4020` returns a real numeric prediction array via
`self.predict()` perturbation with plotting optional — bucket C, not A.
`MultiRegressionCustomMetric`/`MultiRegressionCustomObjective`/
`MultiTargetCustomMetric`/`MultiTargetCustomObjective` don't exist anywhere
in the vendored Python source (grepped the whole package) — they name the
native `PythonUserDefinedMultiTarget` dispatch, which R already implements
and tests via `calc_ders_multi`/`multi_target=TRUE` (`R/catboost.R:1533-1547`,
`tests/testthat/test_custom_objective.R:231-243`) — bucket C.
